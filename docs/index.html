어떻게 동작하나요

조사와 검토를 서로 다른 agent가 맡고, 검토를 통과하지 못하면 고쳐서 다시 검토받습니다.

  1. 1

    주제 입력

    저장소까지 주면 후보 찾기를 건너뜁니다.

  2. 2

    후보 찾기

    모델이 아는 저장소와 대표 저장소 위키에서 언급된 저장소를 모읍니다.

  3. 3

    DeepWiki 확인

    위키가 실제로 있는 후보만 보여 주고 하나를 고르게 합니다.

  4. 4

    조사와 초안

    구조, 연동, 보안, 버전, 운영 고려사항을 정해진 형식으로 씁니다.

  5. 5

    근거 검토

    PASS, WARN, FAIL을 매기고 FAIL이면 고쳐서 다시 검토합니다.

설치

Claude Code 세션에서 두 줄이면 설치됩니다. 키나 토큰은 필요 없습니다.

플러그인 설치

Claude Code 세션에서 차례로 실행합니다.

/plugin marketplace add puttylike/oss-review-kit /plugin install my-kit@capstone-local

업무 폴더 설정

권한 차단과 MCP 허용 목록은 플러그인에 넣을 수 없어서 업무 폴더의 .claude/settings.json에 둡니다.

{ "permissions": { "deny": ["WebSearch", "Read(~/.claude.json)", "Read(~/.config/gh/**)"] }, "allowedMcpServers": [ { "serverUrl": "https://mcp.deepwiki.com/mcp" } ] }

들어 있는 것

  • skilloss-review (도입 검토 리포트), proposal-draft (도입 기획안)
  • agentmcp-researcher (조사), evidence-reviewer (근거 검토, 읽기 전용)
  • hookmcp-guard, net-guard (도구 호출 직전에 검사)
  • MCPdeepwiki (인증 없는 공개 서버)
  • 필요jq (훅 스크립트가 사용)

가드레일

설치한 폴더 어디서든 훅이 함께 따라가서 허용된 곳 밖으로 나가는 호출을 막습니다.

막는 것

  • mcp.deepwiki.com이 아닌 곳으로 나가는 Bash, WebFetch 호출
  • deepwiki가 아닌 MCP 도구와 쓰기 성격의 도구
  • 훅 스크립트가 없거나 깨졌을 때의 모든 도구 호출 (fail-closed)
  • 웹 검색과 인증 파일 읽기 (폴더 설정의 deny 규칙)

알아둘 한계

  • 플러그인 훅은 사용자가 끌 수 있습니다. 조직이 강제하려면 managed 정책으로 내려야 합니다.
  • 훅은 도구 입력 문자열만 봅니다. MCP 서버가 안에서 보내는 요청은 보지 못합니다.
  • DeepWiki에는 저장소 검색이 없어서 공개되고 등록된 저장소만 다룹니다.
